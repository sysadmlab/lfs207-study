## Adding an identity for logging purposes  
An identity is added to a repository for logging purposes - to check what changes have been made and who made it.  
Identity configuration works at three levels:  
Local - applies to one repository  
System - applies to all users and all repositories  
Global - applies to one user and all repositories the user uses  
In this demo, I'm going to add my identity to all the repositories I use. Hence, I choose the **Global** option. <br>

## git add command  
The file **code.txt** currently remains **Untracked** by git, and to make **git** track changes, we use the command **git add**.  
The command **git add code.txt** moves the file **code.txt** to the staging area.  
A file is **Staged** or in the **Staging Area** means that the **file** or **a change to the file** has been marked for inclusion in the next **commit**.  
As shown in the image below, the file which was in status **Untracked** is now **Staged** after executing the **git add** command. <br>  
<img width="813" height="493" alt="image" src="https://github.com/user-attachments/assets/c2689832-0660-41e3-88c0-ad1ecac6d1ad" />  


## git commit command  
When I execute the command **git commit** the snapshot of the file is permanently recorded in the repository.  
The commit operation stores a **snapshot** of the tracked file, who made the change, the date and time of the change, remarks describing the change, link to
a previous commit, and a unique id. <br>  
<img width="727" height="383" alt="Screenshot From 2026-11-15 22-43-26" src="https://github.com/user-attachments/assets/76862804-9843-4cfd-93a8-6f2d4e1f7700" />  
As shown in the image above, the **git commit** command makes a permanent record of the file in the repository.  
The option **-m** allows me to provide a short description of the change for the **commit**.  
By default, **git** requires a short description be provided during the commit, failing which the **commit** operation will not be successful.  
The string **2ea6856** is the unique hash code generated for this commit operation.  

## Modified status of a file  
In this demo, I'm going to open the file **code.txt** and append couple of lines of text. Then, with the **git status** command I will verify the status of the file. </br>  
<img width="752" height="310" alt="Screenshot From 2026-11-16 12-02-42" src="https://github.com/user-attachments/assets/a45f7054-4e48-4e97-961e-433e631c4598" />  
As seen in the image above, the file **code.txt** now has status **modified**. A file that is being tracked by **git** has status **modified** if the 
contents of the file **differ** from the version stored during the last **commit**. The **modified** status is highlighted in **red** if the file have **not** been **staged** yet.  
The status also mentions that **Changes not staged for commit**.  
So for someone who is wondering what has changed in the file, **git** helps in finding those changes.   

## git diff command  
Continuing from my previous demo, I would want to find out what has changed in the file since the last commit.  
To achieve this, I will execute the **git diff code.txt** command <br>  
<img width="687" height="256" alt="Screenshot From 2026-11-17 17-05-47" src="https://github.com/user-attachments/assets/b99f6f86-2167-4db8-803e-4e14388180bb" />  
The **git diff** command compares the old and new versions of the file displays the results.  
In the image above, I note that the line that has remained unchanged is in **grey**, the lines added are coloured in **green** and have a **+** symbol prefixed.  
If some lines were removed, they would be prefixed with a **-** symbol and would be coloured in **red**.  <br>  

I want to accept the changes I have made to the file, hence I would use the command **git add code.txt** - which would move the file to the staging area. <br>  
<img width="682" height="230" alt="Screenshot From 2026-11-17 17-17-21" src="https://github.com/user-attachments/assets/22edb90f-6f36-4a7f-a122-b330797b4e68" />  
The last time I executed the **git add** command, it was the **first time** the file was staged for version control, hence the **git status** command displayed **new file**.  
However, this time the file has already been tracked by **git**, hence I don't see the **new file** status.  
Instead, the status is now **modified** **BUT** highlighted in **green**. It is still a modified file, but it has not been committed yet.  
Now, I will execute the **git commit** command to finalise the changes. <br>

## git log command  
As the name states, the command **git log** displays a log of the changes that the file has undergone: the hash generated for the commit, who made the changes,
the timestamp of those changes. <br>  
<img width="662" height="319" alt="Screenshot From 2026-11-17 17-52-16" src="https://github.com/user-attachments/assets/7f45ac95-502f-4d62-9be7-b3e9a3f29b31" />  
As shown in the image above, the **git log code.txt** command displays the log with the most recent commit first which is denoted by (**HEAD -> master**). Each commit
has the unique hash, the author, the timestamp, and the comment. This log helps in keeping track of changes the file has undergone.
